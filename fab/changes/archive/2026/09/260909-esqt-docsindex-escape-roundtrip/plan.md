# Plan: docs-index — Fix Escape Runaway in Folder-Index Descriptions, and the Hardcoded Glossary Path

**Change**: 260909-esqt-docsindex-escape-roundtrip
**Intake**: `intake.md`

## Requirements

### docs-index: Frontmatter Round-Trip (bug 1)

- **R1** — `frontmatter.Field` MUST unescape Go-quoted (`%q`-written) double-quoted `description:` values so that read and write are inverse operations: for every value `x` (including values containing `"`, `'`, `\`, and non-ASCII), `Field(write(x)) == x`. The write side keeps `%q` (`memoryindex.go` `RenderDomain`) — byte-compatibility with every currently-valid generated index is preserved because `strconv.Quote` output is unchanged. The read side, when a value is double-quoted, MUST attempt `strconv.Unquote` and fall back to the current outer-quote-strip behavior when unquoting fails (hand-authored YAML that is not a valid Go literal keeps today's semantics; no new error paths).
  - GIVEN a folder index whose `description:` contains `an escaped \"quoted\" phrase`, WHEN `fab docs-index` reads it back and rewrites the file, THEN the written description line is byte-identical to the previous run (no backslash doubling).
  - GIVEN a double-quoted frontmatter value that is not a valid Go quoted literal (e.g. an invalid escape), WHEN `Field` reads it, THEN the value is returned exactly as today (outer quotes stripped, interior untouched).
- **R2** — `fab docs-index` MUST be convergent over any tree whose descriptions contain quotes: a second consecutive run over an unchanged tree produces byte-identical files and reports "already up to date" (no `Updated:` lines). A regression test MUST pin this by generating twice into a fixture tree containing adversarial folder-index descriptions and asserting byte-equality of all outputs.
  - GIVEN the intake's reproduction tree (sub-folder index with `description: "Sub with an escaped \"quoted\" phrase"`), WHEN `fab docs-index` runs four times, THEN runs 2–4 leave every file byte-identical to run 1's output.

### docs-index: Configurable Root Nav Note (bug 2)

- **R3** — The hardcoded navigation line in the legacy memory-root render (`RenderRoot` — `> **New here?** … [README](../../README.md) … [Glossary](../specs/glossary.md).`) MUST be removed and replaced by a per-root `docs_index.roots[].nav_note` key (free-text markdown, no built-in default): unset or empty renders nothing; a non-empty string renders verbatim on the root landing (after the "Generated by" note on a generic root), followed by a blank line. The binary carries no consumer-layout paths. *(Amended by user decision after initial review: the original R3 kept the legacy line as the unset default for byte-compatibility; the default was dropped — every repo takes a one-time benign-drift diff on its root memory index, and repos that want the line set `nav_note`.)*
  - GIVEN a repo whose glossary lives at `docs/glossary.md`, WHEN it sets `nav_note` on the memory root and regenerates, THEN the generated root index contains only resolving links and survives regeneration unchanged.
  - GIVEN a repo with no `nav_note` key, WHEN it regenerates, THEN the root index carries no navigation line (a one-time removal diff on first regeneration, byte-stable thereafter).
- **R4** — The new key MUST be registered with `fab config explain` metadata (default/description/scope/advertise) and documented: `src/kit/skills/_cli-fab.md` § fab docs-index and `docs/specs/config.md` § `docs_index.roots` gain the `nav_note` field (Constitution: CLI ⇒ docs + tests).
  - GIVEN `fab config explain docs_index.roots`, WHEN run after the change, THEN the output describes `nav_note` including the unset/empty/set semantics.

### Non-Goals

- **The contrast link `../specs/index.md`** in `RenderRoot`'s preamble ("Contrast with [`docs/specs/index.md`](../specs/index.md)") stays as-is. It is the same defect class but was not the reported breakage, resolves in both known consumer repos, and folding the whole three-paragraph preamble into config or curated ownership is a larger design than this fix warrants. Recorded as assumption 4; a follow-up change can generalize.
- **Self-healing already-runaway values.** After R1, a corrupted description (accumulated `\\…\"` runs) converges — it round-trips stably and stops growing — but the backslashes remain content. Collapsing `\+"` heuristically would mutate legitimately-backslashed descriptions (`back\slash` is valid prose) that the reader cannot distinguish from corruption. Consuming repos fix corrupted values by hand (loom already did); the release note documents this one-time cleanup.
- **A `--check` convergence class.** With R1 fixed the known non-convergence source is gone and R2's idempotency test guards the generator side; a runtime convergence detector would require regenerate-twice-and-compare semantics in `--check` for a bug class that no longer exists. Decision recorded; revisit only if a new non-convergence source appears.
- **Single-quoted YAML `''` un-doubling** in `stripQuotes` — the generator never writes single-quoted values; out of scope.

### Design Decisions

- **Decision**: Fix bug 1 on the read side (`strconv.Unquote` with fallback) and keep `%q` on the write side.
  **Why**: `strconv.Unquote` is the exact inverse of the `%q` writer, and leaving the writer untouched keeps every currently-valid generated index byte-identical — no repo-wide drift diff.
  **Rejected**: Full YAML marshalling on write (changes quoting style of existing valid files — a byte-stability regression across every consuming repo); normalizing/rejecting quotes at write time (lossy, and descriptions legitimately carry quotes like `<Button variant="ghost"/>`).
  *Introduced by*: 260909-esqt-docsindex-escape-roundtrip

- **Decision**: Fix bug 2 with a per-root `nav_note` config key and no built-in default — the generator emits no navigation links of its own.
  **Why**: The generator's job is index tables, not editorial links; any default bakes the consuming repo's layout into the binary (the original bug). The one-time benign-drift diff per repo was accepted by user decision. The curated-block machinery could not carry this instead: `curatedNavigation` deliberately never seeds from an already-generated index (`adoption.go`).
  **Rejected**: Keeping the legacy line as the unset default (the change's initial shape — zero-regression but retains consumer-layout paths in the binary); curated-block seeding (blocked by the never-seed-from-generated rule).
  *Introduced by*: 260909-esqt-docsindex-escape-roundtrip
