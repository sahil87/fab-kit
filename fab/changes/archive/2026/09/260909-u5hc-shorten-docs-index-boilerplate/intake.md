# Intake: Shorten the docs-index Generated Header and Manual-Block Seed

**Change**: 260909-u5hc-shorten-docs-index-boilerplate
**Created**: 2026-09-09

## Origin

Conversational. During a `/fab-discuss` session the user reviewed the diff of PR #658 (kit 2.24.5, `feat: docs-index — Index Every File Type in Generated Navigation, and Rename the Hand-Managed Block to manual`) and asked, of the new generated header on every `docs/memory/**/index.md` and `docs/specs/**/index.md`:

> Isn't this way too verbose? A single line (or at max 2) is needed

The user then invoked `/fab-fff` to run the fix through the pipeline. The shortened wording was proposed in the discussion and is reproduced verbatim under **What Changes**; the user did not object to it.

## Why

**Pain point.** PR #658 replaced the one-line generated note on every primary landing (`> **Generated by \`fab docs-index\`** — do not hand-edit. Descriptions come from each file's \`description:\` frontmatter.`) with:

1. A **blockquote note** that restates the whole manual-block contract — 4 wrapped lines on the memory root (`RenderRoot`) and one ~300-character line on every other landing (`RenderDomain`, `src/go/fab/internal/memoryindex/memoryindex.go:295` and `:329`).
2. A **5-line HTML comment** seeded inside the manual block on creation (`manualBlockSeed`, `src/go/fab/internal/memoryindex/adoption.go:23`) that repeats the same contract a second time plus row semantics and the `--check` tombstone flag.

Together that is ~10 lines of boilerplate before the first table on every landing. It is repeated across 8 committed landings in this repo alone (`docs/memory/index.md`, the 5 domain indexes, `docs/specs/index.md`, `docs/specs/findings/index.md`) and lands on every landing of every consuming repo.

**Consequence if unfixed.** Every index page a human or agent opens leads with two paragraphs of tooling chrome. The header also violates this repo's owner-or-pointer rule (`fab/project/code-quality.md` § Anti-Patterns): the artifact restates rules that `docs/memory/memory-docs/docs-index.md` and `_cli-fab.md` § fab docs-index own — the HTML `<title>`/`<meta>` fallback, description precedence, the `--check` tombstone flag — so the copies drift when the owner changes. And the spec already shows the intended shape: `docs/specs/templates.md` § Memory Index / § Domain Index render the note as a single line (`> **Generated by \`fab docs-index\`** — do not hand-edit.`), so the 2.24.5 output diverged from its own spec.

**Why this approach.** Cut both strings to one line each, keeping only the two facts an agent needs at the point of editing: *regenerate, don't edit* and *the manual block is yours*. The detail stays where it is owned (memory file + CLI reference). Rejected: leaving the long header and only shortening the seed (the blockquote is the part repeated verbatim on every regen); moving the header text to config (chrome should not be a knob — the same reasoning that removed the default `nav_note`).

## What Changes

### 1. Generated header note → one line (both renderers)

`RenderRoot` (`memoryindex.go:295–298`) and `RenderDomain` (`memoryindex.go:329`) both emit the note below, **identically, as one physical line** (no wrapping on the root — the root's wrapped form exists only because the sentence was long):

```markdown
> **Generated by `fab docs-index`** — do not hand-edit; only the manual block below is preserved.
```

Constraints the new text MUST keep:

- The exact prefix `> **Generated by \`fab docs-index\`**` — `insertNavNote` (`docsindex.go:389`), `supersededCleanup`'s remove-detection (`docsindex.go:149–153`, prefix `> **Generated by \`fab ` + `docs-index\``), and `manualNavigation`'s never-seed-from-generated guard (`adoption.go:41`, substring `Generated by \`fab `) all anchor on it.
- The phrase `manual block` so the note names the region it points at.
- The memory root's separate two-paragraph preamble (`> **Memory files are post-implementation artifacts** …` / `> Contrast with … human-curated.`) is **unchanged** — it is the Constitution VI sense of "human-curated", pinned by `TestDocsIndexManualBlockLegacyMemoryRoot`.

### 2. Manual-block seed comment → one line

`manualBlockSeed` (`adoption.go:23–27`) becomes a single-line comment:

```markdown
<!-- Hand-managed rows (non-markdown descriptions, external links, groupings) — preserved verbatim. -->
```

It still names the three residue categories and the preservation guarantee; the place-and-label rule and the `--check` tombstone flag move out of the artifact and stay in the memory file (`docs-index.md` § Manual Block already states both).

Creation-only semantics are unchanged: the seed is written when the generator **creates** a block; an existing block's content passes through verbatim (`TestDocsIndexManualBlockContentPreservedVerbatim`). No re-emission, no sentinel.

### 3. Tests

Update every pin of the old strings so they assert the new one-line forms:

- `golden_test.go` — `TestGolden_RenderRoot_FullDocument` (lines 29–32) and `TestGolden_RenderDomain_FullDocument` (line 61) full-document goldens.
- `memoryindex_test.go:100` — `TestRenderDomain_NoSubDomainsByteIdentical`.
- `docsindex_test.go` — `TestDocsIndexHeaderProse` (line ~834–840: replace the two opposite-verb substrings `don't edit it, re-run the command` / `edit it, it is preserved verbatim` with the new note's substrings, keep the prefix assertion); `TestDocsIndexManualBlockAlwaysEmitted` (line ~763: the block-position anchor `"preserved verbatim.\n"` must anchor on the new header's line end instead); `TestDocsIndexManualBlockLegacyMemoryRoot` and `TestDocsIndexManualBlockContentPreservedVerbatim` use the `manualBlockSeed` constant and keep working, but re-read them for literal substrings.
- Any other test that embeds the old header literal (grep `everything outside the manual block` and `Hand-managed; preserved verbatim` across `src/go/fab`).

Run `go test ./internal/memoryindex/ ./cmd/fab/` (the `cmd/fab` package has docs-index integration tests) — both green.

### 4. Regenerate this repo's landings and hand-trim the existing seed comments

The blockquote is regenerated automatically. The seed comment inside the 8 existing manual blocks is *content*, preserved verbatim, so it does **not** shorten on regen. In this repo, hand-edit each existing manual block to the new one-line comment (editing the manual block is exactly what the block is for), then regenerate every root with the **freshly built** binary — not the Homebrew 2.24.5 binary, which would re-emit the long header:

```bash
cd src/go/fab && go build -o /tmp/fab-dev ./cmd/fab && cd - && /tmp/fab-dev docs-index
/tmp/fab-dev docs-index --check   # expect exit 0 or 1 (benign drift only), never 2
```

Files: `docs/memory/index.md`, `docs/memory/{_shared,distribution,memory-docs,pipeline,runtime}/index.md`, `docs/specs/index.md`, `docs/specs/findings/index.md`. Removing a comment from the manual block is not a row removal, so the tier-2 destructive-loss detectors (description wipe, tombstone drop, grouping flatten) MUST NOT fire — verify with `--check`.

Consuming repos keep whatever seed text they already have (preserved verbatim by design); they pick up the short header on their next regen and can trim the comment by hand if they wish. No migration file — index files are generator output (the `No Migration File for the Marker Rename` precedent in `docs-index.md`).

### 5. Docs

- `docs/memory/memory-docs/docs-index.md`: § Generated Header Prose currently says both renderers "emit a two-sentence note with opposite verbs" and spells the sentences out — rewrite to the one-line note (present truth, no "was" narration); § Manual Block's seed sentence ("it seeds an agent-facing comment stating the contract (hand-managed, preserved verbatim, the residue categories below, the place-and-label rule, the `--check` tombstone flag)") — trim to what the one-liner actually says; add a Design Decision (four-field shape) recording *one line each, detail lives with the owner*. Description frontmatter stays ≤500 chars.
- `src/kit/skills/_cli-fab.md` § fab docs-index ("seeded with an agent-facing comment on creation") stays accurate — no change expected; confirm.
- `docs/specs/templates.md` already shows a one-line note — no change.
