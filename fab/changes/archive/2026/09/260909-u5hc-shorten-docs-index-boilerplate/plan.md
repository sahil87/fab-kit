# Plan: Shorten the docs-index Generated Header and Manual-Block Seed

**Change**: 260909-u5hc-shorten-docs-index-boilerplate
**Intake**: `intake.md`

## Requirements

### memory-docs: Generated Header Note

#### R1: One-line generated header on every primary landing
Both renderers (`RenderRoot` for the legacy memory root, `RenderDomain` for every other landing) MUST emit the identical single-line note `> **Generated by \`fab docs-index\`** — do not hand-edit; only the manual block below is preserved.` followed by one blank line. The prefix `> **Generated by \`fab docs-index\`**` MUST stay byte-identical (it is the anchor for `insertNavNote`, `supersededCleanup`'s remove-detection, and `manualNavigation`'s never-seed-from-generated guard). The memory root's two-paragraph preamble (`Memory files are post-implementation artifacts …` / `… human-curated.`) MUST be unchanged.

- **GIVEN** a `docs_index.roots` root with a primary (`index_file`) landing
- **WHEN** `fab docs-index` renders the landing
- **THEN** exactly one blockquote line beginning `> **Generated by \`fab docs-index\`**` precedes the manual block
- **AND** the line is identical on the memory root and on every domain / sub-domain / generic-root landing
- **AND** a configured `nav_note` still lands immediately after that line

### memory-docs: Manual-Block Seed

#### R2: One-line seed comment on block creation
`manualBlockSeed` MUST be the single-line comment `<!-- Hand-managed rows (non-markdown descriptions, external links, groupings) — preserved verbatim. -->`. Creation-only semantics are unchanged: the seed is written only when the generator creates a block; an existing block's content (either marker spelling) passes through verbatim and the seed is never re-emitted into it.

- **GIVEN** a primary landing with no manual block and nothing to seed-import
- **WHEN** the generator writes it
- **THEN** the manual block contains exactly the one-line seed comment between its markers
- **GIVEN** a landing whose manual block already holds content
- **WHEN** the generator rewrites it
- **THEN** that content is byte-preserved and the seed comment is not added

### memory-docs: This Repo's Landings

#### R3: Repo landings carry the short forms; regen is never destructive
All 8 committed primary landings (`docs/memory/index.md`, `docs/memory/{_shared,distribution,memory-docs,pipeline,runtime}/index.md`, `docs/specs/index.md`, `docs/specs/findings/index.md`) MUST carry the one-line header and the one-line seed comment. Regeneration MUST be performed with a binary built from this branch (the installed 2.24.5 would re-emit the long header), and `docs-index --check` afterwards MUST NOT exit 2.

- **GIVEN** the 8 landings with the 5-line seed comment hand-trimmed to the one-liner
- **WHEN** the branch-built binary runs `docs-index` over every root
- **THEN** every landing's header is the R1 one-liner, the manual block holds the R2 one-liner, and a second run reports no updates (idempotent)
- **AND** `docs-index --check` exits 0 or 1, never 2

### Non-Goals

- Changing the `log.md` header comment (`<!-- Generated by \`fab docs-index\` from git history … -->`) — already one line, different anchor.
- A migration file or a config knob for the header text — index files are generator output; consuming repos pick up the short header on their next regen and may hand-trim their own seed comments.
- Touching `docs/specs/templates.md` (already shows a one-line note) or `_cli-fab.md` § fab docs-index (its "seeded with an agent-facing comment on creation" sentence stays true).

### Design Decisions

#### One Line Each; Detail Lives With the Owner
**Decision**: The generated header and the manual-block seed each carry one line stating only *regenerate, don't edit* and *the manual block is yours*.
**Why**: Every landing led with ~10 lines of chrome that restated rules `docs-index.md` and `_cli-fab.md` own (owner-or-pointer, `code-quality.md`); the spec's own rendering (`templates.md`) was already a one-liner.
**Rejected**: Keeping the long header and trimming only the seed (the header is the part re-emitted on every regen); making the header text configurable (chrome is not a knob — the `nav_note` default was removed for the same reason).
