# Intake: docs-index — Index Every File Type in Generated Navigation, and Rename the Hand-Managed Block to `manual`

**Change**: 260909-l0bf-docs-index-all-files-manual-block
**Created**: 2026-09-09

## Origin

Conversational. The user reported friction from another repo that runs `fab docs-index` over a `docs/specs` tree holding HTML, PNG, and markdown files, then walked through a design discussion that ended with "agreed. go ahead". This intake was created by `/fab-proceed`'s promptless-defer dispatch from the synthesized conversation; no questions were asked of anyone. The user's raw report and the agreed decisions, condensed:

> The block `<!-- fab docs-index:curated:start -->…:end -->` sitting directly under the header line "Generated by `fab docs-index` — do not hand-edit. Descriptions come from each file's `description:` frontmatter." is confusing: the header says don't hand-edit, yet the block is the one region meant to be hand-managed. Nothing in the file explains the split. The block was born as a first-run seed import (preserve legacy rows so the tier-2 loss guard does not trip) and its prose was written for that story; it now also serves as the place for things the generator cannot index, but never says so. A fresh index emits no block at all, so there is no visible slot telling an agent where a non-markdown or external entry goes. The word "curated" collides with Constitution VI vocabulary, where "human-curated" means spec *content*.
>
> Real failures observed: 17 `.html` spec files are invisible to the generator (the walker only treats `.md` as topics); a folder holding a single 102KB HTML file and zero `.md` vanishes entirely (cannot be a sub-domain row, cannot carry a description); a sibling `left-panel/index.md` renders an empty file table while `left-panel-rewrite.html` sits beside it undocumented; a `docs/specs/assets/cursio/` folder with 6 PNGs is absent from the index; that repo's README instructs agents to hand-list HTML files inside the curated markers, which was done for exactly one of 17.
>
> Assumption: humans will not edit these index files; agents manage them by (1) running the binary and (2) adding the exceptions the binary cannot handle.

**Key decisions from the conversation** (each is reproduced in full under What Changes and graded in Assumptions): every regular file is a topic row, with a new per-root `exclude` glob list as the only exclusion mechanism; per-type metadata extraction (markdown unchanged, HTML `<title>`/`<meta name="description">`, everything else filename + `—`); missing-description advisory only for types that can carry one; folder descriptions keep the frontmatter round-trip (no synthesized text); the region is renamed `curated` → `manual` with read-both compatibility and no migration file; the block is always emitted in every primary landing with an agent-facing comment inside; the header prose becomes two sentences with opposite verbs; existing adoption semantics are unchanged; owner-or-pointer sweep of the skills and docs; one-time benign drift accepted.

## Why

**Problem.** `fab docs-index` was built for markdown trees: `docWalk.isTopic` (`src/go/fab/internal/memoryindex/docsindex.go`) returns false for anything not ending in `.md`, and `walk` drops any child folder with `count == 0` and no existing landing. In a specs tree that also holds HTML pages and image assets, three things go wrong at once: non-markdown files never get a row, folders containing only non-markdown files disappear from the parent's Sub-Domains table (so they cannot even carry a description), and a folder mixing one `index.md` with an HTML sibling renders an empty file table that looks like a bug. The only escape hatch is the hand-managed block, but (a) a fresh index never emits it, so there is no visible slot, (b) the header directly above it says "do not hand-edit", and (c) its name — `curated` — reuses the Constitution VI word for spec *content*, blurring exactly the line the flt3 amendment (1.7.0) drew between generated navigation and human-curated specs. The observed result in the reporting repo is 1 of 17 HTML files documented and a README rule nobody follows.

**Consequence of not fixing.** Every consuming repo with non-markdown documentation gets an index that silently lies by omission, and the hand-managed block stays an undiscoverable, misnamed mechanism whose purpose has drifted from "seed import" to "everything the generator cannot do" without saying so. Because agents (not humans) maintain these files, an affordance that has to be discovered by reading the Go source is an affordance that does not exist.

**Why this approach.** The mental model the user and agent converged on is one sentence: *the index is the tree, minus what you exclude.* Every regular file becomes a row; the per-root `exclude` glob (same machinery as `superseded`) is the single opt-out, so the binary bakes in no type policy. Metadata comes from whatever the file type can carry (frontmatter for markdown, `<title>`/`<meta>` for HTML, nothing for the rest), the missing-description advisory fires only where a description *could* exist, and the hand-managed block — renamed `manual`, always present, self-describing via an embedded comment — becomes the documented home for the residue: descriptions for files that cannot carry their own metadata, external links, custom groupings. The rename also removes the vocabulary collision. Rejected alternatives and their reasons are listed at the end of What Changes.

## What Changes

### 1. Every regular file under a root is a topic row

`docWalk.isTopic` (docsindex.go) currently requires a `.md` suffix. It changes to accept **every regular file**, with these exclusions and nothing else:

- the landing files — `index_file` and every `also_accept` name (already excluded today);
- `log.md` and the seed file (`seedFileName`, i.e. `log.seed.md`) on `log: true` roots (already excluded today);
- dotfiles (names starting with `.`);
- symlinks (already skipped in `walk` — "navigation generation must stay within its root");
- anything matching the new per-root `exclude` glob list (§2).

Consequences that follow mechanically from the walker:

- A folder containing only non-markdown files now has `count > 0`, so it is **no longer dropped**: it becomes a real sub-domain with its own generated primary landing (`index_file`) and a row in the parent's `## Sub-Domains` table. In the reporting repo, the folder with one 102KB HTML file and `docs/specs/assets/cursio/` (6 PNGs) both appear.
- Non-markdown files count toward the folder's topic count (the `WidthWarnThreshold` advisory). The index is the tree; `exclude` is the relief valve if a folder of assets pushes a folder over the soft bound.
- `FileEntry.Base`/`Link`: today `Base` is the stem without `.md` and `Link` defaults to `Base + ".md"`. For non-markdown files the link target is the **filename verbatim** (e.g. `left-panel-rewrite.html`), so `Link` is set explicitly and the `.md`-stem fallback applies only to markdown.
- Only `.md` and `.html`/`.htm` files are ever **opened**; every other type is listed from its directory entry alone (no reads of PNGs, PDFs, etc.).
- Sort order stays lexicographic by the link-target stem/filename as today.
- `log: true` roots: FKF frontmatter validation (`sourceWarnings`) runs only on `.md` files — frontmatter is a markdown construct. The `log.md` projection is untouched (it is folder-level git history; non-markdown files get no special handling in this change).

### 2. New per-root `exclude` glob list

Add `Exclude []string` to `config.DocsIndexRoot` (`src/go/fab/internal/config/docs_index.go`), YAML/JSON key `exclude`, default empty, `omitempty`:

```go
type DocsIndexRoot struct {
	Path       string   `yaml:"path" json:"path"`
	IndexFile  string   `yaml:"index_file" json:"index_file"`
	AlsoAccept []string `yaml:"also_accept,omitempty" json:"also_accept,omitempty"`
	Log        bool     `yaml:"log" json:"log"`
	MaxDepth   int      `yaml:"max_depth" json:"max_depth"`
	Superseded []string `yaml:"superseded,omitempty" json:"superseded,omitempty"`
	// Exclude lists root-relative slash globs (same syntax as Superseded) for
	// files or folders the walker must not index at all: not a row, not a
	// count, not a landing. The index is the tree minus these.
	Exclude []string `yaml:"exclude,omitempty" json:"exclude,omitempty"`
	NavNote string   `yaml:"nav_note,omitempty" json:"nav_note,omitempty"`
}
```

Semantics, reusing `matchGlob`/`supersededPath` from `superseded.go` (rename or generalize the helper so both fields share one matcher — no duplicate glob code):

- Patterns are root-relative slash globs: `**` spans directories, `*`/`?`/bracket classes within a segment, literal brackets escaped — identical to `superseded`.
- A **file** matching any pattern is skipped before `f.count++` — it produces no row and does not count.
- A **folder** matching any pattern is not walked at all — no landing, no sub-domain row, no counts; an existing generated landing inside it is left alone (this change does not add cleanup for excluded subtrees — `superseded` already owns the "retire generated output" behavior, and exclusion means "pretend it is not there").
- A folder whose files are all excluded ends with `count == 0` and is dropped exactly like an empty folder today.
- When a path matches both `exclude` and `superseded`, `exclude` wins (it is never seen, so it cannot be counted as superseded).
- `validateGlobs` is parametrized by field name so its error text names `docs_index.roots.exclude` or `docs_index.roots.superseded` correctly; `GatherRoot` validates both lists up front.

Example config (this is what the reporting repo would write to keep its PNG assets out of the index while indexing HTML):

```yaml
docs_index:
  roots:
    - path: docs/specs
      index_file: index.md
      also_accept: [README.md]
      log: false
      max_depth: 8
      superseded: ["**/archive/**"]
      exclude: ["assets/**", "**/*.png"]
```

Registration surfaces (all in the same change):

- `src/go/fab/internal/configref/configref.go` `docs_index.roots` row: extend `Description` to list `exclude ([] glob patterns)` alongside `superseded`, and drop the sentence "First-run curated navigation is imported automatically" in favor of manual-block wording (see §5/§10). Extend `docsIndexSegment` with a commented `#     #   exclude: ["assets/**"]` example line.
- `src/kit/skills/_cli-fab.md` § fab docs-index: document `exclude` (default `[]`) next to `superseded` — same glob paragraph, one sentence on semantics ("the index is the tree minus `exclude`").
- `docs/specs/config.md` § Documentation index roots: add an `exclude` row to the field table and the example entry.
- `src/go/fab/cmd/fab/memory_index.go` `Long` help: add `exclude` to the per-root field list.

### 3. Per-type metadata extraction into the same two slots

`readTopic` (docsindex.go) becomes type-dispatched on the lower-cased extension. All types fill the same two slots the row already has — **label** and **description**:

| Type | Label | Description | Reads the file? |
|------|-------|-------------|-----------------|
| `.md` | unchanged — filename stem; H1 when description is missing in a generic root (legacy memory keeps stems) | unchanged — `description:` frontmatter | yes (as today) |
| `.html` / `.htm` (case-insensitive) | `<title>` text (entities unescaped, whitespace collapsed); filename when absent or empty | `<meta name="description" content="…">` value; `—` when absent or empty | yes — stdlib scan, stops at `</head>` or `<body` |
| everything else | filename (with extension) | `—` | **no** |

Rules that are load-bearing:

- **A `<title>` MUST NEVER be used as the description.** Through the adoption path (§9) a generated description replaces a manual row's description whenever the generated one is non-`—`; a title-as-description would therefore clobber hand-written manual rows on every regeneration. The title is a label source only.
- HTML extraction uses the standard library only (no `golang.org/x/net/html` dependency — `go.mod` today has exactly cobra + yaml): a case-insensitive scan for the first `<title>…</title>` and the first `<meta …>` tag whose attributes include `name="description"` (either attribute order, single or double quotes), unescaped via `html.UnescapeString`. The two tags live in `<head>`, so the scan stops at `</head>` or the first `<body` — a self-contained page with a large inline `<style>` before `<title>` is still handled because the whole head is scanned, not a fixed byte prefix.
- Table-cell escaping of labels/descriptions goes through the existing `renderDescription(…, d.Generic)` path — a `|` inside an HTML `<title>` is escaped like any markdown label.

### 4. Missing-description advisory fires only for types that can carry one

`KindMissingDescription` (`⚠ … has no description: — using H1 and placeholder`) is emitted for `.md` (as today) and for `.html`/`.htm` (when the meta description is absent/empty — message wording adjusted so it does not claim "H1" for HTML, e.g. `has no <meta name="description"> — using <title> and placeholder`). It is **not** emitted for any other type: a PNG cannot carry a description, so nagging about it is noise. The advisory kind name and JSON `warnings[]` shape are unchanged (additive only).

### 5. Sub-domain row description for a non-markdown-only folder

Comes from the generated landing's `description:` frontmatter round-trip (`readFolder` → `frontmatter.Field(landing, "description")` → `RenderDomain` writes it back with `%q`), exactly as for every folder today. A brand-new folder that holds only HTML/PNG files therefore starts with `—` in the parent's Sub-Domains row until an agent writes a `description:` stub into its generated `index.md` frontmatter (the same stub-before-index discipline the hydrate skills use). **Do NOT synthesize text** like "1 HTML file" — consistency of the round-trip contract wins.

### 6. Rename the region `curated` → `manual`

- Markers become `<!-- fab docs-index:manual:start -->` / `<!-- fab docs-index:manual:end -->`.
- `adoption.go`: rename `curatedStart`/`curatedEnd` → `manualStart`/`manualEnd`, add `legacyCuratedStart`/`legacyCuratedEnd` holding the old spelling, rename `curatedNavigation` → `manualNavigation` and update its comments. `manualNavigation` recognizes **both** spellings when reading (`manual` first, then the legacy `curated` pair); `adoptNavigation` **always writes** the new spelling. The read-both window is one version: this change ships both; dropping recognition of `curated` is a follow-up for the next minor after this one ships (no removal code here).
- Loss-guard user-facing text: `cmd/fab/memory_index.go` line 303 `destructive loss — regenerating would wipe curated/historical content:` → `… would wipe hand-managed/historical content:`; the `Long` help's `(curated description wipe, tombstone drop, custom grouping flatten)` → `(description wipe, …)`; `loss.go` comments that say "curated description"/"curated text" become "hand-managed"/"existing" wording. The JSON `losses[].category` values (`description`/`tombstone`/`grouping`) are unchanged.
- The rename is **byte-visible** in every existing index that carries a block (this repo: `docs/specs/index.md`), producing one-time benign drift (§11).
- **No `src/kit/migrations/` file.** Index files are generator output, not user data: the binary reads both spellings and rewrites on the next run, so there is nothing for a user to do. This is a **judgment call against** the code-quality anti-pattern "Restructuring existing user data without a migration" and against the flt3 precedent (`2.23.17-to-2.24.0.md` shipped an informational nothing-to-do migration for the `memory-index` → `docs-index` rename). It is flagged here so review does not treat the absence as an oversight; if review or the user wants the announce-only precedent followed, adding a nothing-to-do migration is a one-file addition that changes no behavior.

### 7. Always emit the manual block in every primary landing

Today `adoptNavigation` emits a block only when `existing` already had one (or when first-run seed import found legacy rows). After this change every **primary** (`index_file`) landing — root, domain, sub-domain, in every root including the legacy `docs/memory` root rendered by `RenderRoot` — carries the block, **even when empty**, so the affordance is uniform. Alternate landings (`also_accept`, e.g. `README.md`) do **not** get it: outside their generated block the whole file is already the human-owned region, so a second hand-managed region would be redundant.

Placement is unchanged: immediately before the first table (after the "Generated by" note and any `nav_note`), which is where `adoptNavigation` inserts it today (`boundary := strings.Index(generatedRest, "| ")`).

When the generator **creates** a block (the landing had none, and first-run seed import found nothing to import), the block is seeded with the agent-facing comment below. When a landing already has a block — either spelling — its content is preserved **verbatim** (markers renamed only); the comment is content the adoption loop passes through like any non-row line, not scaffolding re-emitted every run. An existing block that lacks the comment (this repo's `docs/specs/index.md` with its 18 seed-imported rows) does not gain it automatically; the apply hand-inserts it once there as part of the dogfood regeneration — a legitimate edit, since it is inside the manual region.

Empty-block form written on creation:

```
<!-- fab docs-index:manual:start -->
<!-- Hand-managed; preserved verbatim on regeneration. Add rows the generator
     cannot produce: non-markdown files' descriptions (HTML, PDF), external links,
     custom groupings. A row for a file the walker also indexes keeps its place and
     label here, but its description follows that file's frontmatter. A row
     whose target no longer exists is flagged by `fab docs-index --check`. -->
<!-- fab docs-index:manual:end -->
```

The exact wording may be tuned during apply; the **semantics are fixed**: hand-managed, preserved verbatim, the three residue categories (descriptions for files that cannot carry their own metadata, external links, custom groupings), the place-and-label-kept/description-follows-source rule, and the `--check` tombstone flag. Since every file now gets a generated row, the block's stated purpose deliberately narrows to that residue.

Golden/byte-compat fixtures for the legacy memory root (`TestDocsIndexZeroConfigGoldenCompatibility`, `golden_test.go`, `freeze_test.go` expectations) are updated to the new output — the user accepted a one-time drift on **every** root, which includes `docs/memory`.

### 8. Rewrite the generated header prose

Both renderers (`RenderRoot` for the legacy memory root, `RenderDomain` for every other landing — `memoryindex.go` ~lines 286–287 and 318) replace the current "do not hand-edit … Descriptions come from each file's `description:` frontmatter" line with **two sentences with opposite verbs** — proposed text, wording tunable, semantics fixed:

```
> **Generated by `fab docs-index`** — everything outside the manual block below is regenerated from the tree and each file's own metadata (`description:` frontmatter, HTML `<title>`/`<meta name="description">`): don't edit it, re-run the command. The manual block is the one hand-managed region: edit it, it is preserved verbatim.
```

- "Descriptions come from frontmatter" is folded into the first sentence (as the metadata parenthetical).
- The legacy memory root keeps its "post-implementation artifacts / contrast with specs" preamble paragraph above this note. Its sentence "Specs … are human-curated" is the Constitution VI sense (spec *content*) and stays; the word "curated" is dropped everywhere it named the **block** or its rows — generated output, `Long` help, loss-guard messages, `_cli-fab.md`, configref description, memory files.
- `insertNavNote` anchors on the `> **Generated by \`fab docs-index\`**` prefix and the following blank line — the new note keeps that prefix, so the anchor still resolves.
- `supersededCleanup` recognizes generated landings by the `> **Generated by \`fab ` header prefix — unchanged by the rewrite.

### 9. Manual-block semantics rely on existing adoption behavior, unchanged

`adoptNavigation` is not redesigned. Restating the behavior that already exists so plan generation can write acceptance items against it:

- A manual row whose target the walker also indexes **keeps its place and label** in the block; its description is **replaced by the generated one when the generated one is non-`—`**, and kept when the generated one is `—`. The generated row for that target is removed from the generated table so a target appears once.
- A manual row for a target the walker does not know (external link, non-existent local path) is passed through; a local target that no longer exists is what `tombstoneLosses` flags (`--check` exit 2 on a drift run; first-run rows get the `<!-- fab docs-index:historical -->` tombstone marker).
- Deleting a manual row whose target lacks its own description trips the tier-2 loss guard (`descriptionLosses`, exit 2) — that is the guard working as designed, not a regression to fix.
- Non-row lines inside the block (prose, headings, the seeded comment) pass through verbatim.

### Rejected alternatives (with why)

- **Hardcoded built-in list of "asset" extensions to skip** — replaced by the per-root `exclude` glob; keeps the one-sentence mental model and avoids baking type policy into the binary.
- **Listing non-markdown files as `—` rows with no description source at all** — HTML gets `<meta name="description">`; other types use the manual block for hand-written one-liners.
- **A `fab docs-index add <root> <row>` subcommand so agents never touch the file** — a whole command plus tests for a problem a five-line comment solves.
- **Keeping the name "curated"** — collides with Constitution VI's "human-curated specs" vocabulary.
- **Synthesizing folder descriptions ("1 HTML file")** — keep the frontmatter round-trip for consistency.
- **Shipping a migration file for the marker rename** — index files are generated output; read-both compat in the binary suffices (judgment call, flagged in §6).
- **Re-emitting the seeded comment into every block on every run** — would violate "preserved verbatim" and need a sentinel heuristic that double-inserts once the wording is tuned; seed-on-create is simpler and the one existing block in this repo is hand-fixed during dogfood.
- **Adding `golang.org/x/net/html`** — a full tokenizer for two tags in `<head>`; a stdlib scan is enough and keeps `go.mod` at two direct dependencies.

### Non-goals

- PDF metadata extraction (no library; filename label only).
- Pruning this repo's 18 seed-imported specs rows (follow-up; would trip the loss guard today).
- Any change to Constitution VI — 1.7.0 already permits generated navigation in `docs/specs`; this change authors no spec content.
- The reporting repo's structural issues (deep nesting, topic-count soft bound) — advisories already exist and work as designed.
- Cleanup of previously generated landings inside a newly `exclude`d subtree (`superseded` owns retirement; exclusion means "not there").
- Removing recognition of the legacy `curated` spelling (next-minor follow-up).
