# Plan: Autopilot Merge-Mode Config Default

**Change**: 260821-r5t5-autopilot-merge-mode-config-default
**Intake**: `intake.md`

## Requirements

### Config: the `autopilot.merge_mode` registry key

#### R1: Config struct field + nil-safe accessor
`internal/config` SHALL model a new `Autopilot` section (`Config.Autopilot AutopilotConfig`, `yaml:"autopilot"`) with a `MergeMode string` field (`yaml:"merge_mode"`), read through a nil-safe accessor `GetAutopilotMergeMode() string` that returns the configured value when non-empty and `DefaultAutopilotMergeMode` when the config is nil or the field is empty. The accessor SHALL NOT validate the value (no warn-and-fallback) — validation is the consuming command's policy (R5), a deliberate divergence from `GetDispatchMode`'s fail-open posture.

- **GIVEN** a config with no `autopilot:` key
- **WHEN** `GetAutopilotMergeMode()` is called
- **THEN** it returns `DefaultAutopilotMergeMode` (`cherry-pick-ladder`)
- **AND** a config with `autopilot: {merge_mode: stacked-prs}` returns `stacked-prs`, and an invalid value like `merge-everything` is returned raw (the caller validates)

#### R2: Single-sourced default + valid-modes list
The default value SHALL live in `internal/agent`'s embedded `defaults.yaml` under a new `autopilot:` block (`merge_mode: cherry-pick-ladder`), init-injected into a literal-free `config.DefaultAutopilotMergeMode` var — the exact `DefaultDispatchMode` pattern. The valid-modes enum SHALL be exported once as `config.ValidAutopilotMergeModes = []string{"cherry-pick-ladder", "merge-auto", "stacked-prs"}` (fab-owned policy, Go-side like the `GetDispatchMode` switch); `cmd/fab`'s `validAutopilotModes` var SHALL be replaced by references to that symbol so no second literal list exists anywhere. A test SHALL pin that the injected default is a member of the valid list (and equals its first entry).

- **GIVEN** the built binary
- **WHEN** `internal/agent`'s `init()` runs
- **THEN** `config.DefaultAutopilotMergeMode == "cherry-pick-ladder"`, matching `defaults.yaml`'s `autopilot.merge_mode` (wiring-guard test, mirroring `TestConfigDispatchDefaultsMatchDefaultsFile`)

#### R3: Registry row + paired scope entry
`internal/configref` SHALL gain an `autopilot.merge_mode` row — `Default` interpolated from `config.DefaultAutopilotMergeMode` (never a copied literal), kind string, `Scope: both`, `Advertise: true`, with its own `Segment`/`ShortSegment` rendering a new commented `# autopilot:` YAML block (no existing row owns that parent, unlike `dispatch.column_width` which rides `dispatch.mode`'s segment). `internal/configscope` SHALL gain the PAIRED entries: `"autopilot": ScopeBoth` in `keyScopes` and `"autopilot.merge_mode"` in the ordered dotted-key list (the 4v91 paired-entry rule — a missing pair breaks every configref consumer wholesale). The generic env mapping then yields `FAB_AUTOPILOT_MERGE_MODE` for free.

- **GIVEN** the new row and paired scope entry
- **WHEN** `fab config explain autopilot.merge_mode` runs
- **THEN** it prints the owning segment with default `cherry-pick-ladder`, scope `both`, and the machine-wide `fab config set --system` pointer
- **AND** `fab config set --system autopilot.merge_mode stacked-prs` is accepted (scope both), and the managed fence regenerated by `fab config upgrade` carries the commented advert

### Binary: `fab operator autopilot start` mode resolution

#### R4: Flag > config > built-in resolution with printed source
`fab operator autopilot start` SHALL resolve the mode by the ladder: `--mode` flag when explicitly passed (detected via `cmd.Flags().Changed("mode")` — the flag keeps its current default for help text), else the config value (`GetAutopilotMergeMode()`), else the built-in default. On success it SHALL print `mode: <name> (<source>)` where `<source>` ∈ `flag` / `config` / `default` (`start` prints nothing today — this is additive stdout).

- **GIVEN** no `--mode` flag and a config with `autopilot: {merge_mode: stacked-prs}`
- **WHEN** `fab operator autopilot start --queue a1,b2` runs
- **THEN** the persisted autopilot block carries `mode: stacked-prs` and stdout shows `mode: stacked-prs (config)`
- **AND** with `--mode merge-auto` also passed, the flag wins (`mode: merge-auto (flag)`); with neither, `mode: cherry-pick-ladder (default)`
- **AND** an explicit `--mode cherry-pick-ladder` reports source `flag` (Changed-detection, not value comparison)

#### R5: Invalid config value errors actionably
When the config-sourced value is not in `ValidAutopilotMergeModes`, `start` SHALL exit non-zero with an error naming the config key and the valid set (e.g. `invalid autopilot.merge_mode %q in config (valid: cherry-pick-ladder, merge-auto, stacked-prs)`), writing no state. Flag validation is unchanged (`unknown --mode %q (valid: …)`). Merging is destructive-tier: silently falling back to a different topology than the one configured is the wrong failure mode.

- **GIVEN** a config with `autopilot: {merge_mode: merge-everything}` and no `--mode` flag
- **WHEN** `start` runs
- **THEN** it exits non-zero naming `autopilot.merge_mode` and the valid set, and no autopilot block is written

#### R6: Neutral-dir config resolution + untouched back-compat fill
`start`'s config load SHALL work from the operator's natural fab-less cwd: resolve `resolve.FabRoot()`; on success load via `config.Load(fabRoot)`; on failure fall back to `config.LoadPath` of the cwd-relative `fab/project/config.yaml` (an absent project file still composes the system + env tiers), so a `~/.fab-kit/config.yaml` preference reaches an operator launched from a neutral parent directory. A config load error is fail-soft (treat as empty config → built-in default) — a broken config must not brick queue start when no override was asked for. `loadAutopilot`'s absent-`mode` back-compat fill SHALL keep reading as the built-in default (`DefaultAutopilotMergeMode`), never config-resolved — the mode was fixed at queue start and persisted; re-resolving at read time could silently retopologize a running queue.

- **GIVEN** no `fab/` project anywhere up the tree and `~/.fab-kit/config.yaml` carrying `autopilot: {merge_mode: stacked-prs}`
- **WHEN** `start` runs without `--mode`
- **THEN** the mode resolves to `stacked-prs (config)`
- **AND** a pre-existing state file whose autopilot block lacks `mode` still reads as `cherry-pick-ladder` regardless of config

### Skill: `fab-operator.md` §6 silent resolution

#### R7: Silent default rule with in-confirmation veto
`src/kit/skills/fab-operator.md` §6 Autopilot SHALL state: when the user's queue request names no mode, the operator resolves it via the ladder (explicit user instruction / `--mode` > config `autopilot.merge_mode` > built-in `cherry-pick-ladder`) and proceeds WITHOUT asking; the resolved mode is stated inside the existing upfront queue-confirmation line (which already varies by mode), so the user vetoes in the same breath — no extra round-trip. The operator learns the config value from `start`'s printed `mode: … (source)` line (it never parses config files itself).

- **GIVEN** a queue handoff naming no merge mode
- **WHEN** the operator starts the queue
- **THEN** it does not ask "which merge topology?"; the confirmation line names the resolved mode and its source

#### R8: Pause-and-ask only on the two enumerated misfits
The skill SHALL enumerate exactly two misfit cases where the operator pauses and asks instead of proceeding silently: (a) the resolved mode is `merge-auto` but the queue has same-repo `depends_on` entries (implicit chaining is disabled in that mode — the declared dependency semantics contradict it); (b) the user's own message conflicts with the resolved mode (e.g. "merge as you go" while the resolved mode is a held mode). No other condition triggers the mode question.

- **GIVEN** config resolves `merge-auto` and the queue carries same-repo `depends_on`
- **WHEN** the operator prepares the queue
- **THEN** it pauses and asks the mode question (R9 format) rather than starting

#### R9: Mode-question format + caveat scoping
When the operator DOES ask the mode question, the skill SHALL require the question to include the at-a-glance glyphs (`▂▄▆` cherry-pick-ladder · `░▒▓█` merge-auto · `▄▀` stacked-prs), the three compact box diagrams, and a one-line tradeoff per mode. The existing parenthetical "never emit them into the status frame" SHALL be reworded to make its scope explicit: the prohibition is status-frame-only; a mode question is an ordinary conversational message where fenced diagrams render fine.

- **GIVEN** a misfit triggered the mode question
- **WHEN** the operator asks
- **THEN** the question carries glyphs + diagrams + tradeoffs, and the skill text no longer reads as banning diagrams from all output

### Non-Goals

- No migration file — the key is new and optional; no existing user data is restructured.

- No re-resolution of a running queue's mode from config (explicitly rejected — R6).

### Design Decisions

#### Default value rides `defaults.yaml`; the enum stays Go-side
**Decision**: `autopilot.merge_mode`'s default lives in the embedded `defaults.yaml` (`autopilot:` block) and is init-injected into a literal-free `config.DefaultAutopilotMergeMode`; the valid-modes list is the exported Go symbol `config.ValidAutopilotMergeModes`.
**Why**: `defaults.yaml` is documented as "the single value source for every built-in default" and everything in it is user-overridable via the same config key — exactly this key's shape; the enum is fab-owned policy (which values are accepted), matching `GetDispatchMode`'s Go-side switch.
**Rejected**: a plain Go literal default in `internal/config` (creates the second default-source convention the wll4 consolidation exists to kill); putting the enum in `defaults.yaml` (an accepted-values list is policy, not tunable data).
*Introduced by*: 260821-r5t5-autopilot-merge-mode-config-default

#### Accessor returns raw; `start` owns validation
**Decision**: `GetAutopilotMergeMode()` does absent→default only and returns invalid values raw; `fab operator autopilot start` validates and errors.
**Why**: the error-not-fallback posture is command policy (destructive-tier merge topology), and only the command knows the value's source for an actionable message; keeps the accessor consistent with document-don't-validate.
**Rejected**: `(value, error)` accessor shape — forces every future reader to handle an error only `start` cares about.
*Introduced by*: 260821-r5t5-autopilot-merge-mode-config-default
