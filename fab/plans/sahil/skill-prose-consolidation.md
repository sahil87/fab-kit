# Skill prose consolidation — src/kit/skills sweep

> Backlog detail doc — written 2026-08-08 after a `/fab-discuss` audit of all 36
> files in `src/kit/skills/` (8,703 lines / ~108k words), run as six parallel
> sub-agent analyses (five file groups + one cross-file duplication sweep).
> **Analysis baseline**: commit `6f74e0c3` (v2.16.19, post-#538); findings
> re-verified against `b05ab998` (v2.16.20, post-#539/#540/#541). Line refs are
> baseline refs — expect ±a few lines in `_preamble.md`, `_cli-fab.md`,
> `_cli-agents.md`, which #539/#540 touched. The work is split into **four
> phases in dependency order**, each independently shippable as its own fab
> change, intended to be picked up by an operator/agents later.

## Goal

Cut ~15,000 words (~20%) from the skill corpus with **zero contract loss**, fix
the 10 live defects the audit surfaced, and change the policies that let the
bloat accumulate — so the corpus stays lean. The dominant disease is one
pattern: **restating a contract instead of pointing at its owner**, which costs
tokens on every load and has already produced five real drift bugs.

Headline evidence that this is correctness work, not just tidying: PR #539
(`fab dispatch reap`) updated the canonical dispatch contract in `_preamble.md`
— and none of the downstream restatements in `_pipeline.md`, `fab-continue.md`,
`fab-adopt.md`. Every restated copy now silently omits the reap step. That is
the drift mechanism in action, one day after the audit measured it.

## Non-goals

- No behavioral change to any skill. Every phase is prose-only (phase 4 also
  amends two policy files and adds a partial).
- No compression of the protected set (§ Must NOT be compressed, below).
- `docs/memory/` and `docs/specs/` content changes beyond the constitution-
  required SPEC mirrors.

## Execution constraints (read before starting any phase)

1. **SPEC mirrors**: every `src/kit/skills/*.md` edit requires the matching
   `docs/specs/skills/SPEC-*.md` update in the same change (constitution,
   Additional Constraints; review treats the *whole* mirror class as in-scope —
   see `fab/project/code-quality.md` § Sibling & Mirror Sweeps).
2. **Canonical source only**: edit `src/kit/skills/`, never `.claude/skills/`
   (deployed copies, gitignored, regenerated by `fab sync`).
3. **Twin sweeps**: `fab-ff` ↔ `fab-fff` are twins; aggregate specs
   (`skills.md`, `glossary.md`, `architecture.md`) restate per-skill facts —
   grep the old phrase repo-wide before finishing apply.
4. **The `helpers:` allow-list in `_preamble.md` (§ Skill Helper Declaration)
   is closed** — adding `_git`/`_reorg` partials (phase 4) requires editing
   that list; it is not a drop-in.
5. **Word counts, not line counts**: the corpus writes one paragraph per
   physical line; several "lines" are 200–400 words. Savings below are quoted
   in words where the source analysis did.
6. Re-verify line refs against HEAD before editing — #539/#540 shifted
   `_preamble.md` (~+6 lines), `_cli-fab.md` (~+40), `_cli-agents.md` (±0).
