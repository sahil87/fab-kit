1 · What a tick does today

Every tick runs the seven steps in §4 Tick Behavior. Each step reads one section of the state file and talks to one external source. The picture is worth drawing because the gaps are structural, not accidental: whole classes of tracked things have no arrow to anything that observes the world.

2 · Where PR #913 fell through

The self-analysis in the screenshot is accurate about the symptom. The cause sits in the skill text, not in the session's discipline.

Three lines in the skill together produce this outcome:

  • §4 Notes, routing doctrine. “Merge-gate dependency waits (checked by operator judgment per tick — no git/GitHub watch source exists today)” go to a note. The gap is documented as policy.
  • §4 Tick Behavior step 4. The only GitHub poll in the tick is “if a merge sequence is in progress”, meaning a PR the operator itself armed. A PR someone else will merge is never polled.
  • §4 Idle Message. “The idle message is the only other per-tick output … nothing else.” On a quiet tick the agent is told to say nothing, so there is no moment where it would naturally re-read open notes and re-verify them.

The Go side agrees with the prose: operator_watch.go rejects any --source other than linear or slack, and tick-start only enumerates tmux panes. So your read is right. The tracked-thing model is fab-change-shaped, and everything else is a special case bolted to its side.

3 · One tracked-item model

The fix is not a sixth section for GitHub. It is to make every tracked thing the same shape, so that the binary can poll all of them in one loop and the LLM only decides what to do about changes. The operator's job statement then becomes literally what you said: hand me something long-running, I will watch it and act when it moves.

What this buys you, in the terms of the #913 incident: fab operator track add pr-913 --probe 'gh pr view 913 --json state' --done '.state==\"MERGED\"' --then 'spawn n34…' would have produced a done delta on the first tick after 22:07:54, and the operator would have spawned n34 without being asked.

4 · The frame

The table the operator prints every tick is the only surface where a stale item can be seen. Today it has two tables (changes per repo, then watches), no column for when a thing was last verified, and no row for notes. 5 · Simplifications, in order

  1. Replace the five state sections with one tracked list.

    Each item: id, kind, probe (pane | shell <cmd> | agent <instruction> | none), done_when, then (prose), depends_on, last, checked_at. Monitored entries, watches, autopilot queue entries and coordination notes become kinds with defaults. The clock predicate becomes “tracked is non-empty”, which is simpler than today's four-clause disjunction. branch_map can stay as a side lookup, or ride as item metadata.

  2. Make tick-start --diff poll every item with a mechanical probe.

    Today it enumerates panes. Extend it to run shell probes (bounded timeout, argv-only, stderr swallowed) and evaluate done_when as a small predicate over the probe's JSON. Items whose probe is agent come back in a needs_check block with their age, so the LLM is told what to verify rather than trusted to remember. This single change closes the #913 class of bug.

  3. Keep the git choreography in the main skill; tighten it in place. decided 2026-09-11

    Dependency resolution, the three merge modes, ordered merge and auto-merge are 235 lines, but they are the operator's main job, and they must survive a compaction reload: an armed merge sequence whose procedure lives in a helper the operator has to remember to load is the #913 shape again. So they stay where the reload guarantees them. In the generic model they operate on items with depends_on rather than on a separate autopilot block, which removes the duplicated "satisfied" definitions and the note-based persistence of the merge sequence. Realistic trim in place: 235 to about 180 lines. The three mode diagrams stay; the mode question requires them.

  4. Demote fab-only rules from principles to the fab-change kind.

    “Route pipeline-first”, “spawn in a worktree”, the hard wt gate at startup, stage-validated flags and “completion = review-pr done” are all correct for a fab change and wrong for everything else you listed. Keep them as the defaults that kind carries. A task kind whose then is “open an agent tab with this prompt” covers a normal change; a linear kind with no then covers a ticket you merely want to watch.

  5. One frame, one table (§4).

    Replace the change table plus watches table plus the ten-row element-format table with a single table over items: id, kind, state, age since check, next. Keep the health emoji as the only colour channel and keep the compact quiet-tick line. An item not verified within its expected cadence shows ⚠ unverified 14m, which is the visual that would have caught #913 by tick #5121.

  6. Notes become items with probe: none, and they render.

    Drop the four note kinds and the routing-doctrine table. A note is a tracked item a human will resolve; it shows in the frame with its age, and the “stale after 14 days” flag already exists in note list. This also removes the paragraph that currently tells the agent merge-gate waits are its unaided responsibility.

  7. Prune the operational scaffolding once the model is uniform.

    Candidates: the two-rung version-skew fallback, the pre-cron /loop fallback (rk is a hard dependency of the operator in practice), the duplicate no-fence warnings, the Spawn-Session inference's four evidence tiers (default to “session of the target repo's other agents, else ask once”), and the “Idle Message” section. Each is defensible alone; together they are why the file is 903 lines.

6 · What to keep untouched

  • The clock. Cron-driven bare operator tick, mute on empty, lease as bounded snooze, no slash command in the payload. This was hard-won and is correct.
  • Binary owns state. Every mutation through a verb, atomic writes, level-triggered deltas with remove-as-ack. The generic model relies on exactly this.
  • Auto-nudge. The waiting-first sweep, the answer model, non-blocking strategic handling and the re-capture guard. None of it is fab-specific.
  • Pre-send validation and confirmation tiers. Also kind-agnostic already.
One caution on shell probes. A probe string in the state file is executed by the binary on every tick. That is fine for a user-owned XDG file, but the verb should refuse a probe that is not an argv list, run it with a short timeout, and never pass it through a shell. The rk cron respawn argv in §4 already follows that shape.

7 · The clock: which cron kind

Verified against run-kit's backoff.go, not only the doc page. The ladder's anchor is the operator pane's own last non-clock activity: an agent-state epoch within 120 seconds of the entry's latest delivery is attributed to the tick and the ladder keeps climbing; an epoch outside that window is genuine activity and resets to rung 0.

KindAnchorSees external changePane-only operatorGeneric tracking

backoffoperator pane's last genuine idleby polling, thinning to 30mbest with wake_onpoor: floor erodes
--idle-every 9aupsame, flat ladder (min = max)by polling at a fixed floor, re-phased on your activityfinebest with skip-if-busy
wake_onother panes' state edgesnoessentialessential for agent items only

What 9aup adds, and why it changes the answer

  • deliver: skip-if-busy is a third delivery policy beside immediate (type it in, harness queues it) and when-idle (hold, retry each poll, drop after two hours). Busy is active or waiting. A dropped tick costs nothing: ticks are idempotent and the important deltas are level-triggered.
  • --idle-every d is backoff with min equal to max. Both objections to backoff vanish at a flat ladder: there is no rung to lose, so a long tick turn only re-phases, and the interval never thins.
  • rk cron edit turns the clock into a knob the operator owns. §4's "cadence is not owned by this skill" flips.

Recommended entry for the generic operator

schedule:  idle-every 3m            # every 3m when no epoch is available
wake_on:   { event: agent-state-change, scope: server, debounce: 60s }
deliver:   skip-if-busy             # no queued tick backlog, no tick after every exchange
if_absent: respawn · pinned

Two consequences to accept: a wake_on fire that lands mid-turn is dropped too, so the interval must stay short; and an operator parked on its own permission prompt skips every tick until answered, which is why it runs with bypass permissions.

Who turns the knob

The operator changing its own schedule "as the work changes" is right in aim and wrong if it is a per-tick LLM judgment, which is the #913 failure class again. The split that works:

  1. LLM decides cadence per item, once, at track add.

    "CI here takes about 8 minutes", "poll the deploy every 2 minutes until green". It becomes the item's check_every.

  2. Binary derives the entry's schedule from the tracked set.

    No external items: backoff 1m→30m, keeping the fade. Any external item: idle-every min(check_every) with skip-if-busy. Applied through rk cron edit on the same hook that mutes and unmutes, only when the derived value changes.

  3. User overrides conversationally, bounded.

    "Hold the ticks for 30 minutes" stays a lease. "Check every 15 minutes for the rest of the day" is an edit with an expiry the reconcile respects.

  4. The frame shows the live cadence.

    Ready line and compact tick line carry every 3m · skip-if-busy or backoff 1m→30m, read from rk cron list --json, never from memory.

Mechanical note for run-kit: switching kinds re-anchors. A switch to every 3m fires on the next poll if the gap already exceeds 3 minutes. Harmless, but the edit spec should say so.

8 · Substrate: fab pane vs rk mux

Both, layered. The operator still calls fab pane map --all-sessions and tick-start --diff, but since the cli-layering work those source their pane list from rk mux panes --json whenever rk is present, with a silent tmux fallback. rk is the substrate; fab adds change, stage and PR enrichment from the worktree's status files.

  1. A probe-fingerprint wake source. rejected

    Decision: probes stay in fab. A raw output fingerprint has too many unrelated ways to change, so it would wake the operator on noise. The mitigation belongs where the item is defined: at track add the LLM names the field to compare (.state, .mergedAt), and tick-start diffs only that. Original proposal kept for the record: wake_on: { event: probe-change, argv: [gh, pr, view, "913", --json, state], every: 2m }. rk polls external state inside its own 30-second ticker and fires the operator only on change. Polling leaves LLM turns entirely, the operator stays on backoff, and the #913 class is closed at the substrate. It has a target and a delivery, so it fits rk's own scope rule. A repo-boundary decision: settle it before the fab tracked-item work.

  2. A spawn verb. released · wzve

    rk tab new takes no session target, cwd or command. A verb taking -t session, -c cwd, the command, a name, optional --ready, printing {session, window_id, pane_id} deletes §6 step 7 and its escaping paragraph.

  3. Window marking through options, with setters. released · hzih

    rk renders @rk_win_marker, @rk_win_color, @rk_win_note but they are set only by raw tmux set-option. A rk tab mark verb plus a "tracked by operator" treatment retires the »/› rename hack.

  4. Liveness in the enumeration row. released · 7pek

    Add has_agent to rk mux panes --json so tick-start can drop its own process-tree walk, the most intricate code in the operator binary.

  5. Structured schedule in rk cron list --json. released · r5ao

    Today schedule is the display string backoff 1m→30m. Deriving and editing needs {kind, min, max, interval}, deliver and wake_on as fields.

  6. Prompt classification. released · a7g2

    fab pane questions is substrate work living in fab. An rk mux capture --classify is its natural home. Small and last.

Not a gap: fleet waiting. rk mux await --any blocks the caller and needs re-arming; the cron wake_on edge already does that job without a foreground process.

9 · With rk released: what else leaves the prose

Two facts change the arithmetic. First, the operator already cannot run without run-kit in any useful way: the clock, the role mark, the send gate and the spawn readiness probe are all rk. Second, the skill loads four helpers, and the biggest of them is a reference for every fab command when the operator uses four. The cuts below assume 9aup and the five backlog items are shipped.

  1. Make run-kit a hard dependency and delete every fallback.

    27 rk-absent or raw-tmux fallback passages in the skill and 12 in _cli-agents: raw send-keys, the /loop degraded clock, the ntfy / Discord / PushNotification / Slack notify ladder, rk-less pane-map notes, the two-rung version-skew procedure, and every scattered command -v rk gate. One startup check replaces them: rk present and at or above the version carrying the six verbs, else stop with the install line.

  2. Load the operator's slice of _cli-fab.md, not the file.

    1,475 lines loaded, about 400 used: fab operator, fab pane, fab agent, fab resolve. Split those into _cli-operator.md, or make helpers section-addressable in the frontmatter. This is the single largest context saving available and needs no run-kit change.

  3. Pre-send validation becomes "send via rk mux send; a refusal is the answer".

    §3 items 1 and 2 and _cli-agents § Pre-Send Validation paraphrase rk's own gate table. Keep the policy line: --answer for waiting, --force only on explicit user confirmation. The Delivery Probe section goes too; the paste probe and bounded recovery are rk's.

  4. Spawn is one call.

    rk tab new --session =S --cwd <wt> --name <n> --ready --json -- <cmd> returns {session, window_id, pane_id}; track add reads them. §6 step 7, the escaping paragraph, and the -P -F explanation go. Session inference keeps the three-line majority rule over rk mux sessions; the four-tier prose goes.

  5. Markers replace renames.

    rk tab mark and rk tab note replace the »/› choreography, its exit-code handling and the "window rename skipped" log line. fab pane window-name leaves the operator entirely.

  6. The clock section shrinks to the rule and the knob.

    Structured rk cron list --json renders the ready line from fields, so the four literal variants collapse to one template. Delete the seeded-entry YAML copy and the "how the union predicate covers the retired loop" history. Add the derived-schedule rule and rk cron edit in three lines.

  7. Question detection is rk mux capture --classify.

    The §5 detection paragraph and the fab pane questions contract pointer become one line over the tick's waiting-first candidates. The answer model and the strategic table stay; they are the skill's judgment, not substrate.

  8. agent_exited reads has_agent.

    The longest bullet in _cli-fab § tick-start, the shell-basename list and the process-tree walk semantics, becomes: command is a shell and has_agent is false.

  9. Probe contract, given the boundary decision.

    Every mechanical probe declares the fields it compares; tick-start never diffs raw output. That is the false-positive guard the rejected rk wake could not offer, and it is why the field choice sits with the LLM at track add.
