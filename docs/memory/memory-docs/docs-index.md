# Docs Index

**Domain**: memory-docs

## Overview

`fab docs-index [<root-path>] [--check] [--json] [--rebuild]` is the deterministic docs-index generator (Go: `cmd/fab/memory_index.go` + `internal/memoryindex/`), generalized from the memory-only generator to run over any configured documentation root. With no argument it processes every `docs_index.roots` entry; a positional argument selects one configured root (an unconfigured path errors naming the config key; there is no `--root`). With no `docs_index` configuration the implicit root is `{path: docs/memory, index_file: index.md, log: true, max_depth: 3}` and output is byte-identical to the pre-generalization generator. `fab memory-index` remains as a deprecated memory-only alias (one stderr deprecation notice, JSON stdout clean, kept for at least one minor version). Every regular file under a root is a topic row — the index is the tree minus the root's `exclude` globs — and every primary landing carries a hand-managed `manual` block (see Manual Block below). The full command contract — flags, exit tiers, JSON shape, glob syntax, older-binary version-skew fallback — lives in `$(fab kit-path)/skills/_cli-fab.md` § fab docs-index; the memory-root index/log ownership contract lives in [templates](/memory-docs/templates.md) and [hydrate](/memory-docs/hydrate.md) § Index Ownership Model; the specs-root adoption in [specs-index](/memory-docs/specs-index.md).

## Requirements

### Configured Roots (`docs_index.roots`)

`docs_index.roots` is a project-scoped config sequence registered with `fab config explain` metadata (default/description/scope/advertise). Per-root fields: `path` (required, repo-root-relative), `index_file` (default `index.md` — the generated landing filename), `also_accept` (default empty — alternative landing filenames such as `README.md`), `log` (default `false`; the implicit zero-config memory root defaults it `true` — opt-in FKF `log.md` freeze-on-write), `max_depth` (default `3` — soft-warn depth bound), `superseded` (default empty — glob patterns marking superseded material), `exclude` (default empty — root-relative slash globs sharing the `superseded` matcher, naming files or folders the walker must not index at all: no row, no count, no landing; a matched folder's whole subtree is skipped, an excluded-to-empty folder is dropped like an empty folder, and `exclude` beats `superseded` on a double match — the index is the tree minus `exclude`), `nav_note` (default empty — the root landing's navigation note, primary landings only: unset or empty renders nothing, a non-empty value renders verbatim — on a generic root landing, right after the "Generated by" note; the generator emits no navigation links of its own). Overlapping or duplicate roots are rejected. Schema detail: [config.md](../../specs/config.md) § `docs_index.roots`.

### Arbitrary-Depth Recursion

The generator recurses to arbitrary depth: every content-bearing folder gets a generated landing file and the parent index links child folders. `max_depth` is an advisory bound only — a deeper tree warns on stderr and still generates; it never truncates traversal and never fails generation.

### Landing-File Ownership

An `index_file` landing is a whole generated file. A folder whose existing landing file matches `also_accept` keeps it: the generated index table is written into a marker-delimited block (`<!-- fab docs-index:generated:start -->` / `:end -->`) inside that file, prose outside the block is human-owned and byte-preserved, and no neighboring `index_file` is created. Only generated index files/blocks are rewritten — everything else in the tree is human-owned.

### All Regular Files Are Topics

Every regular file under a root is a topic row — the index is the tree, minus what the root excludes. The exact exclusion list: the landing files (`index_file` and every `also_accept` name), `log.md` and `log.seed.md` on `log: true` roots, dotfiles (name starts with `.`), symlinks (never followed — navigation generation stays within its root), and paths matching the root's `exclude` globs. No extension-based filtering remains. A folder holding only non-markdown files has `count > 0`, so it is not dropped: it becomes a sub-domain with its own generated primary landing and a row in the parent's `## Sub-Domains` table. Non-markdown files count toward the folder's topic count (the width advisory; `exclude` is the relief valve for asset folders). A non-markdown row's link target is the filename verbatim (e.g. `left-panel-rewrite.html`); `.md` keeps its stem-based link, and sort order stays lexicographic by link target.

### Per-Type Metadata

`readTopic` dispatches on the lower-cased extension; every type fills the same two row slots — label and description:

- **`.md`** — unchanged: `description:` frontmatter as the description; H1 as the label when the description is missing in a generic root (the legacy memory render keeps filename-stem labels); link target defaults to the stem + `.md`.
- **`.html` / `.htm`** (case-insensitive) — label from the `<title>` text (entities unescaped, whitespace collapsed; filename fallback when absent or empty); description from `<meta name="description" content="…">`, `—` when absent or empty. Extraction is a standard-library, case-insensitive scan of the `<head>` region — bounded by `</head>` or the first `<body`, not a fixed byte prefix — for the first `<title>…</title>` and the first `<meta>` tag carrying `name="description"` in either attribute order and either quote style. **A `<title>` is never used as the description** (see Design Decisions).
- **Every other type** — label is the filename with extension, description `—`, and the file is never opened (listed from its directory entry alone).

Folder descriptions keep the frontmatter round-trip unchanged: a folder holding only non-markdown files starts with `—` in the parent's Sub-Domains row until a `description:` stub is written into its generated landing; the generator never synthesizes folder text.

### Missing Descriptions Degrade Gracefully

A file without a description source emits a row with a `—` placeholder description — never a generation failure, and the generator never invents one. The `missing-description` advisory fires only for the types that can carry a description: `.md` (a generic-root row is labelled by its H1; the legacy memory render keeps filename-stem labels for byte compatibility) and `.html`/`.htm` (an HTML-specific message that does not claim "H1" — `has no <meta name="description"> — using <title> and placeholder`). It does not fire for any other type — a PNG cannot carry a description, so nagging about it is noise. Advisory kind names and the `--json` `warnings[]` shape are unchanged (additive only).

### Superseded Subtree Rendering

`superseded` is a list of root-relative slash globs (`**` spans directories; `*`, `?`, bracket classes within a segment; literal brackets escaped, e.g. YAML-quoted `'**/\[archived\]-*'`) naming the **status**, not the rendering. A path matching any pattern is superseded; everything else is current:

- **At the parent index** the whole superseded subtree is one row — folder name, a summary (`{N} superseded versions ({v1}–{vN}), {M} files` for versioned children with numeric version bounds; otherwise `Superseded — {M} files`) — with no per-file rows.
- **At the superseded folder's own index**: one row per immediate child folder (`Superseded` plus the child's own landing-stub `description:` when present) with a file count. Per-file rows are never emitted inside a superseded subtree.
- **Descriptions are never read from files inside a superseded subtree** — only counts and folder names (the walk skips file reads under superseded paths).
- A `superseded` pattern matching an individual **file** folds into its parent folder's `{K} superseded files` count note — no per-file rows anywhere.
- When a live subtree becomes superseded, regeneration removes its obsolete generated descendant landings and logs (an alternate landing loses only its generated block; human prose and seed inputs remain), and `--check` reports the configured retirement as benign drift.

### Manual Block

Every **primary** (`index_file`) landing — the legacy memory root, generic roots, domains, sub-domains — carries a hand-managed block delimited by `<!-- fab docs-index:manual:start -->` / `<!-- fab docs-index:manual:end -->`, placed immediately before the first table (after the "Generated by" note and any `nav_note`). Alternate (`also_accept`) landings never receive one — outside their generated block the whole file is already human-owned, so a second hand-managed region would be redundant. The block is always emitted, even when empty, so the affordance is uniform. When the generator **creates** a block (the landing had none and seed import found nothing), it seeds a one-line agent-facing comment — `<!-- Hand-managed rows (non-markdown descriptions, external links, groupings) — preserved verbatim. -->` — naming the residue categories and the preservation guarantee; an existing block — either spelling — is preserved **verbatim** with markers renamed only (the comment is content the adoption loop passes through, not scaffolding re-emitted every run). The place-and-label rule and the `--check` tombstone flag are documented here, not in the artifact.

The block's purpose is the residue the generator cannot produce: **descriptions for files that cannot carry their own metadata** (HTML, PDF), **external links**, and **custom groupings**. Since every regular file gets a generated row, a hand-written row for an indexed file is only needed to supply that file's description.

Row semantics (adoption): a manual row whose target the walker also indexes **keeps its place and label**, and its description is replaced by the generated one only when the generated one is non-`—`; the generated duplicate row is removed so a target appears once. A row whose target is unknown or external passes through; a row whose local target no longer exists is what the tombstone detector flags on `--check`. Deleting a manual row whose target lacks its own source description is a tier-2 destructive loss — the guard working as designed.

The legacy `<!-- fab docs-index:curated:start -->` spelling is still recognized when reading (the read-both window is one version) and is always rewritten as `manual`; no migration file ships — index files are generator output, rewritten on the next run (see Design Decisions).

**First-run seed import**: on the first generation over a root with pre-existing hand-maintained landing files, the generator reads the existing rows/descriptions and imports them into the manual block — seeding placeholder descriptions from imported rows where files lack `description:` — so nothing hand-written is lost and the tier-2 destructive-loss guard does not trip; later regenerations retain full destructive-loss detection. No adopt/force flag and no mandatory frontmatter backfill — an existing repo has to do nothing.

### Generated Header Prose

Both renderers (`RenderRoot` for the legacy memory root, `RenderDomain` for every other landing) emit the identical one-line note `> **Generated by \`fab docs-index\`** — do not hand-edit; only the manual block below is preserved.` followed by one blank line. The `> **Generated by \`fab docs-index\`**` prefix is the anchor that `insertNavNote`, `supersededCleanup`'s remove-detection, and `manualNavigation`'s never-seed-from-generated guard key on. The note states only the two facts an editor needs at the artifact — regenerate rather than edit, and the manual block is the hand-managed region; the contract's detail (metadata sources, row semantics, `--check`) is owned here and in `_cli-fab.md` § fab docs-index. The memory root's preamble sentence "Specs … are human-curated" is the Constitution VI sense (spec *content*) and stays.

### Bounded Warning Reporting

Advisory reporting is bounded: details are capped at **5 per kind across all selected roots**, on stderr and in the JSON `warnings` array; stderr prints an `… and N more (M total)` summary per truncated kind, and the additive `warnings_total` integer counts all JSON-eligible advisories before sampling. Width/depth shape warnings remain stderr-only and are excluded from `warnings_total`. Blocking findings and losses are never sampled. A sampled `warnings` list is not an exhaustive inventory — consumers treat derived counts as lower bounds when `warnings_total > len(warnings)`. Advisory kinds: `description-length`, `missing-description`, `narration-density`, `file-size`, `unsorted-nonempty`, `broken-link`.

### FKF Machinery Scoped to `log: true` Roots

FKF-specific machinery applies only to `log: true` (memory-shaped) roots: `fkf_version` root frontmatter, per-folder `log.md` freeze-on-write generation, `log.seed.md` seed-merge, C-lite joins, `_shared/`/`_unsorted/` reserved-domain exemptions, the FKF §3.2 blocking description escalations (registry-gated change-id in `description:`, gross over-cap >1000 runes), and the narration-density / bundle-relative broken-link diagnostics. A `log: false` root generates indexes and no `log.md`, keeps the generic malformed-frontmatter blocking class and the generic size/length/missing-description advisories, and never interprets site-root links as FKF bundle paths. `--rebuild` is meaningful only for `log:`-enabled roots.

### Safety Contract, Generalized Per Root

Output remains byte-stable / idempotent — a pure function of content, no git dates on the index side — across all roots. `--check` keeps the graded exits **0** clean / **1** benign drift / **2** destructive loss with worst-root aggregation across roots, the blocking floor at 1 (independent of drift, never tier-2), and the `--json` report keys `tier`/`drift`/`losses`/`malformed`/`warnings` (additive keys allowed, none removed or renamed). The tier-2 destructive-loss detectors (description wipe, tombstone drop, custom-grouping flatten) apply to every root, and the refuse-before-regen guards in `/docs-hydrate-memory`, `/docs-reorg-memory`, `/docs-distill-memory`, and `/fab-continue` hydrate continue to key on exit 2 unchanged (see [hydrate](/memory-docs/hydrate.md) § Refuse-Before-Regen Guard).

### Frontmatter Round-Trip Contract

Folder-index landings round-trip their own `description:` through regeneration, so read and write are exact inverse operations: `Field(write(x)) == x` for every value `x`, including values containing `"`, `'`, `\`, and non-ASCII. The write side is `%q` (Go-quoting) in `RenderDomain`; the read side (`internal/frontmatter` `Field`) unescapes a double-quoted value via `strconv.Unquote`, falling back to the plain outer-quote strip when the value is not a valid Go quoted literal (hand-authored YAML keeps the previous semantics; no new error paths). Convergence is pinned by a double-generation regression test (`TestDocsIndexConvergesWithQuotedDescriptions`) over adversarial folder-index descriptions: a second run over an unchanged tree is byte-identical and reports no updates. Descriptions carrying accumulated backslash runs (`\\…\"`) from past escape-runaway corruption converge stably under this contract but keep the backslashes as content — the generator does not self-heal them; consuming repos hand-fix.

### Deprecated Alias

`fab memory-index` runs the new code against the `docs/memory` root only, with the same flags, printing a one-line deprecation notice to **stderr** (never stdout — `--json` consumers parse stdout). It is retained for at least one minor version; removal is a future change. Kit skills never rely on the alias except inside older-binary version-skew fallback prose — the one sanctioned in-kit use; additional-root generation cannot fall back through the alias. See [migrations](/distribution/migrations.md) for the nothing-to-do migration note.

## Design Decisions

### One Generalized Generator, Not a Fork

**Decision**: Generalize the existing memory-index generator to configurable roots rather than writing a second generator for spec trees.
**Why**: Forking diverges and loses the hardened safety machinery — the graded `--check` exit codes, blocking-vs-advisory split, destructive-loss classifier, freeze-on-write logs — that multiple changes built. Generalizing preserves byte-stable navigable indexes, drift detection, and merge-conflict immunity for every doc root.
**Rejected**: A second, specs-specific generator (duplicated safety machinery, divergence); leaving spec trees hand-indexed (staleness and hot-row merge conflicts — the failure mode the generator exists to kill).
*Introduced by*: 260908-flt3-root-agnostic-docs-index

### Status-Named Knob, Pattern List

**Decision**: The config knob is `superseded:` — named for the folder/path **status** — taking a list of glob patterns that may match folders or files.
**Why**: Superseded material in a real tree is marked several ways at once (`archive/` subtrees, `[archived]-`-prefixed filenames, `Z`-prefix folder conventions); a pattern list accepts all of them, and file-level matches fold into the parent folder's count so no per-file rows appear anywhere. Naming the status mechanizes a rule the repo already records in its versioning docs (superseded versions are kept and point forward) rather than encoding one rendering choice.
**Rejected**: A rendering-named knob (`collapse:`) — names a side-effect, not the concept; a single hardcoded `archive/` marker — silently misses content marked the other ways.
*Introduced by*: 260908-flt3-root-agnostic-docs-index

### Seed-Import Over an Adopt Flag

**Decision**: First-run adoption over a hand-maintained root is automatic seed-import — existing rows/descriptions are read into the generated output's manual block, with no adopt/force flag and no refuse-until-backfill step.
**Why**: An existing repo then has to do nothing: nothing hand-written is lost, and the tier-2 destructive-loss guard does not trip on a tree the generator has never seen. The imported navigation stays visible in the always-emitted manual block instead of a hidden sidecar or topic-body rewrites.
**Rejected**: An explicit adopt/force flag (a mandatory manual step every existing repo would trip over); refuse-until-backfill (blocks first use and couples adoption to a frontmatter migration generic roots don't need — sparse-description trees degrade gracefully by design).
*Introduced by*: 260908-flt3-root-agnostic-docs-index

### Generated Navigation Carved Out of Human-Curated Specs (Constitution VI)

**Decision**: Constitution VI (1.7.0) permits tooling-generated index/navigation files inside `docs/specs/` while specification content stays human-curated; prose outside marker-delimited generated blocks remains human-owned. This repo dogfoods the carve-out with a configured `docs/specs` root (`log: false`, `also_accept: [README.md]`, `max_depth: 8`, `superseded: ["**/archive/**"]`).
**Why**: A generated index table is a navigation aid — it authors no specification content, so the specs-are-human-curated principle is preserved while spec trees gain byte-stable indexes, drift detection, and merge-conflict immunity.
**Rejected**: Keeping the recorded no-generator stance (spec trees stay hand-indexed or fork the generator); generating into spec topic files themselves (would author content, not navigation).
*Introduced by*: 260908-flt3-root-agnostic-docs-index

### Package Name Kept (`internal/memoryindex`)

**Decision**: The Go package keeps its `internal/memoryindex` name with a root-aware API (`GatherRoot`, `docsindex.go`, `superseded.go`, `adoption.go`) rather than renaming to `internal/docsindex`.
**Why**: The existing render, classifier, and FKF utilities are reusable as-is; a package rename churns imports and history while adding no behavior.
**Rejected**: Rename to `internal/docsindex` — clean but pure churn.
*Introduced by*: 260908-flt3-root-agnostic-docs-index

### Frontmatter Read/Write Kept as Exact Inverses

**Decision**: The folder-index escape-runaway fix lives on the read side — `Field` unescapes double-quoted values with `strconv.Unquote`, falling back to the outer-quote strip — while the write side keeps `%q`.
**Why**: `strconv.Unquote` is the exact inverse of the `%q` writer, and leaving the writer untouched keeps every currently-valid generated index byte-identical — no repo-wide drift diff across consuming repos.
**Rejected**: Full YAML marshalling on write (changes the quoting style of existing valid files — a byte-stability regression across every consuming repo); normalizing or rejecting quotes at write time (lossy, and descriptions legitimately carry quotes like `<Button variant="ghost"/>`).
*Introduced by*: 260909-esqt-docsindex-escape-roundtrip

### Root Nav Note as Per-Root Config

**Decision**: The root landing's navigation note is a per-root config key, `nav_note`, with no built-in default — unset or empty renders nothing, a non-empty value renders verbatim. The binary carries no consumer-layout paths (no README/glossary links).
**Why**: The generator's job is index tables, not editorial links; any default navigation line bakes the consuming repo's layout into the binary (the original `../specs/glossary.md` bug). Dropping the default costs each existing repo a one-time benign-drift diff on its root memory index — accepted by user decision over keeping the legacy line as an overridable default. Manual-block ownership could not carry this instead: `manualNavigation` deliberately never seeds from an already-generated index (`adoption.go`).
**Rejected**: Keeping the legacy "New here?" line as the unset default (retains consumer-layout paths in the binary and three-state presence=intent semantics for one line of chrome); manual-block seeding (blocked by the never-seed-from-generated rule).
*Introduced by*: 260909-esqt-docsindex-escape-roundtrip

### No Self-Heal for Already-Corrupted Descriptions

**Decision**: Descriptions carrying accumulated backslash runs from past escape-runaway corruption converge under the fixed round-trip but keep their backslashes; the generator does not collapse them.
**Why**: A collapse heuristic cannot distinguish corruption from legitimate backslash content (`back\slash` is valid prose) — it would mutate content the generator does not own. Consuming repos hand-fix their corrupted values; the release note documents the one-time cleanup.
**Rejected**: Collapsing `\+"` → `"` on read (mutates legitimately-backslashed descriptions the reader cannot tell apart from corruption).
*Introduced by*: 260909-esqt-docsindex-escape-roundtrip

### Exclude Glob Over a Hardcoded Asset List

**Decision**: The only opt-out from "every file is a row" is the per-root `exclude` glob list, sharing the `superseded` matcher.
**Why**: Keeps the one-sentence mental model (the index is the tree minus what you exclude) and bakes no file-type policy into the binary.
**Rejected**: A built-in list of asset extensions to skip — silently wrong for any repo whose "assets" are documentation.
*Introduced by*: 260909-l0bf-docs-index-all-files-manual-block

### Title Is a Label, Never a Description

**Decision**: HTML `<title>` fills only the label slot; description comes solely from `<meta name="description">`.
**Why**: Adoption replaces a manual row's description whenever the generated one is non-`—`; a title-as-description would clobber hand-written manual rows on every regeneration.
**Rejected**: Falling back to the title for the description — destroys the manual block's one remaining purpose.
*Introduced by*: 260909-l0bf-docs-index-all-files-manual-block

### No Migration File for the Marker Rename

**Decision**: Ship read-both compatibility in the binary and no `src/kit/migrations/` entry; legacy `curated` marker recognition is deliberately temporary and drops in a later minor.
**Why**: Index files are generator output, not user data; the next `fab docs-index` run rewrites them and there is nothing for a user to do.
**Rejected**: A nothing-to-do announce migration (the flt3 precedent) — the announce cost buys nothing when the binary rewrites the files itself.
*Introduced by*: 260909-l0bf-docs-index-all-files-manual-block

### Seed the Agent Comment Only on Block Creation

**Decision**: The agent-facing comment is written when the generator creates a block; existing blocks are preserved verbatim with markers renamed.
**Why**: "Preserved verbatim" is the block's contract; re-emitting would need a fragile sentinel and double-insert once wording is tuned.
**Rejected**: Re-emitting the comment every run.
*Introduced by*: 260909-l0bf-docs-index-all-files-manual-block

### One Line Each for the Header Note and the Seed Comment

**Decision**: The generated header note and the manual-block seed comment are each a single line stating only *regenerate, don't edit* and *the manual block is yours*; both renderers emit it unwrapped.
**Why**: Every primary landing otherwise leads with ~10 lines of chrome that restate rules this file and `_cli-fab.md` own (owner-or-pointer, `code-quality.md`), and the spec's own rendering in `templates.md` is a one-liner.
**Rejected**: Keeping the long header and trimming only the seed (the header is re-emitted on every regen); a config knob for the header text (chrome is not a knob — the same reasoning that removed the default `nav_note`); a migration to trim existing seed comments in consuming repos (the seed is preserved-verbatim content by design; repos hand-trim if they wish).
*Introduced by*: 260909-u5hc-shorten-docs-index-boilerplate

### Stdlib Head Scan Over an HTML Tokenizer

**Decision**: Extract `<title>`/`<meta name="description">` with a bounded stdlib scan of `<head>`.
**Why**: Two tags do not justify `golang.org/x/net/html`; `go.mod` stays at two direct dependencies; a head-bounded scan handles self-contained pages with large inline styles.
**Rejected**: Adding the tokenizer; a fixed byte-prefix scan (misses titles after large `<style>` blocks).
*Introduced by*: 260909-l0bf-docs-index-all-files-manual-block
