# Migration: 2.28.16 to 2.29.0

> The exact version range is a placeholder — the slot this change ships in is
> release-owned and set at release time.

## Summary

The operator moves to HexoKit. When the installed `rk` lists both `check` and
`brief` under `rk operator --help`, rk owns the operator end to end:

- `fab operator track …`, `tick-start`, `clock sync` (and the `state`,
  `branch-map`, `time` verbs) print one deprecation line to stderr; `track`
  and `tick-start` delegate to `rk operator track …` / `rk operator check`,
  `clock sync` shows `rk cron list`, and `track clock` points at
  `rk cron edit` / `rk cron mute`.
- fab stops writing rk's cron file: no `rk cron add`, `mute`, or `edit` from
  any path, so rk's loop entry is the only unmuted operator clock.
- `/fab-operator` becomes a short pointer that follows `rk skill operator`;
  fab's previous operator skill ships as the internal `_operator-legacy`
  partial and is read only when rk cannot serve the skill.

Without such an rk every `fab operator` verb behaves exactly as before.

**This migration performs no file edits, and the binary moves no data.** fab's
operator state file is only ever read — by `rk operator adopt`, which imports
its tracked items into rk's own state.

## Pre-check

1. Run `rk operator --help`. If its command listing carries both a `check` and
   a `brief` row, continue. Otherwise (rk absent or older) this migration is a
   no-op: fab's operator keeps working unchanged.

## Changes

None to files. The hand-over is a per-server procedure, done with the user:

1. Stop or idle the old operator chat.
2. Upgrade fab and rk.
3. Run `rk operator adopt --dry-run`, then `rk operator adopt`. It is
   idempotent; fab's state file is only read.
4. The rk daemon seeds the target-less `operator loop` entry and mutes — never
   deletes — the legacy `operator tick` entry once rk's state file exists.
   Confirm with `rk cron list`.
5. Open the new chat via `rk operator`.
6. Watch one wake → check → run → note cycle.

Rollback: mute the `operator loop` entry and unmute the legacy `operator tick`
entry (`rk cron mute <id>` / `rk cron mute <id> --off`). fab's state file was
never modified.

## Verification

1. `rk cron list` shows exactly one unmuted operator clock.
2. `fab operator clock sync` prints the deprecation line and unmutes nothing.
