# Migration: 2.19.4 to 2.20.0

## Summary

Remove the retired `branch_prefix` key from `fab/project/config.yaml` (and, as
hygiene, from `~/.fab-kit/config.yaml`).

`branch_prefix` was an optional prefix that only `fab batch switch` applied when
naming a worktree branch (`{branch_prefix}{folder_name}`). As of 2.20.0 the key
is **retired outright** — the struct field, its accessor, its registry row, and
its scope-table entries are gone, and `fab batch switch` names branches by the
change folder name, which is the one branch-naming convention `/git-branch`,
`/fab-new`, and `docs/specs/naming.md` already share.

**Why it is retired rather than honored.** `fab batch switch` attaches worktrees
to *existing* changes, whose branches were created **unprefixed** by
`/fab-new`/`/git-branch`. A project that set `branch_prefix: "feature/"` therefore
had batch switch probe for `feature/<folder>`, find nothing, and create a **new
orphan branch** carrying none of the change's commits, while the change's real
branch sat untouched. The key was a loaded gun the managed fence advertised to
every project.

**Nothing breaks before this migration runs.** The key is unregistered as of
2.20.0, so a `branch_prefix:` left on disk is an inert unknown key — the loader
ignores it silently, exactly as it does a stale `review_tools` or
`agent.spawn_command`. This migration removes the dead key so it stops reading
like a live setting. There is no destination: unlike `review_tools` (→
`fab/project/code-review.md` § Review Tools) or `agent.spawn_command` (→
`providers.claude.interactive_command`), the behavior it configured no longer
exists anywhere.

**Both scopes are swept, for different reasons.** `branch_prefix` was
`scope: project`, so only `fab/project/config.yaml` could carry it *effectively*
— a copy in the system config `~/.fab-kit/config.yaml` was already pruned with a
`fab: warning: ignoring project-scoped field "branch_prefix"` on every load, and
after retirement it is merely an inert unknown key. Sweeping the system file is
therefore hygiene rather than a fix, but the worktree/system-sweep lesson from
`2.15.7-to-2.15.8` says a migration that touches only one location strands the
other, so both are cleaned.

**Also retired, with nothing on disk to migrate**: the environment override
`FAB_BRANCH_PREFIX` (derived from the registry's dotted-key enumeration) no
longer resolves. Environment variables are not project files, so there is no
migration step for it.

The **managed reference fence** needs no step here: `fab config upgrade`
regenerates it from the registry on every `fab upgrade-repo`, so the
`# branch_prefix — …` advert block disappears by itself.

No `.status.yaml` schema change, no binary capability pre-check (pure YAML
editing), no `fab/` data change beyond `config.yaml`, and no commit (the project
config is committed by the user in their own change; the system config is not in
git).

The migration is named FROM=released `2.19.4`, TO=next-minor `2.20.0` per the
`DiscoverMigrations` naming rule and the `2.16.19-to-2.17.0` chaining precedent —
a config-schema removal is a minor. The `src/kit/VERSION` bump to `2.20.0` is
**release-owned** and is not made by the change that authored this file.

## Pre-check

1. **Nothing to do.** If neither `fab/project/config.yaml` nor
   `~/.fab-kit/config.yaml` exists, skip this migration entirely. Print:
   `Skipped: no config.yaml in either scope.`
2. **Sentinel (idempotency).** Skip when **neither** file carries a live
   top-level `branch_prefix:` key. Print:
   `Skipped: branch_prefix already absent (retired key).`
   (Re-running is a complete no-op.)
3. **Live keys only.** A target key must be a **live** YAML key whose name begins
   at column 0 — commented lines (`# branch_prefix: ""`) are reference scaffold,
   never rewritten. In particular the managed fence between the
   `# >>> fab reference` / `# <<< end fab reference` anchors is entirely
   commented and is regenerated by `fab config upgrade`; leave it untouched. A
   `branch_prefix:` nested under any other key is not a target either.

## Changes

Apply to **each** of `fab/project/config.yaml` and `~/.fab-kit/config.yaml` that
exists and carries a live top-level `branch_prefix:` key. Preserve every other
key, value, comment, and the file's indentation style verbatim. Use an **atomic
write** (temp file in the same directory, then `rename`).

### 1. Delete the `branch_prefix:` key

Remove the column-0 `branch_prefix:` line, plus any immediately-adjacent comment
line that documented it (a `# branch_prefix — …` note directly above or below the
key, if present). Leave a single blank-line boundary — do not collapse unrelated
blank lines.

```yaml
# before
project:
    name: myproj
# branch_prefix — optional prefix applied by fab batch switch.
branch_prefix: "feature/"
test_paths:
    - '**/*_test.go'

# after
project:
    name: myproj
test_paths:
    - '**/*_test.go'
```

- The key was a scalar, so there is no nested block to carry: the deletion is
  always a single line (plus its optional adjacent comment).
- If the value was non-empty (a prefix was actually in use), print
  `Warning: <path> carried branch_prefix: "<value>" — the key is retired and 'fab batch switch' now names branches by the change folder name. Existing '<value><folder>' branches are yours to keep, rename, or delete.`
  A prefixed branch holds none of its change's commits (that is the bug this
  retirement fixes), so nothing is migrated for it — the user decides.

### 2. Report

Print one line per rewritten file:
`Removed the retired branch_prefix key from <path>.`

Files that exist but carry no live target key are skipped silently (this is what
makes the per-file step idempotent and re-run-safe).

## Verification

1. Neither file carries a live `branch_prefix` key:
   `yq '.branch_prefix' fab/project/config.yaml` prints `null` (same for
   `~/.fab-kit/config.yaml` when present).
2. Nothing else moved: `yq -o=json '.'` over each config (JSON output strips
   comments) differs from the pre-migration config only by the removed
   `branch_prefix` key.
3. YAML still parses: `yq '.' fab/project/config.yaml` succeeds (exit 0).
4. `fab config show` no longer lists a `branch_prefix` row (the key is gone
   from the file — `show` echoes the raw merged document, so it would still
   appear if a live key remained), and `fab config explain branch_prefix`
   refuses with `ERROR: unknown config key "branch_prefix"` (exit 1).
5. The regenerated managed fence advertises no `branch_prefix` block:
   `fab config upgrade` then
   `grep -c branch_prefix fab/project/config.yaml` prints `0`.
6. Branch naming is prefix-free: for a change whose branch already exists,
   `fab batch switch <change>` checks out `<change-folder-name>` itself (visible
   in the opened worktree's `git branch --show-current`), never a prefixed
   variant.
7. Re-running this migration is a complete no-op: the Pre-check sentinel trips
   (`Skipped: branch_prefix already absent (retired key).`) and nothing is
   changed.
