# Migration: 2.23.17 to 2.24.0

## Summary

Nothing to do for existing memory-only projects. `fab docs-index` replaces the command
name with a root-aware generator. Without `docs_index` configuration it processes
`docs/memory` with `index.md`, logs enabled, and the advisory depth bound of 3.
`fab memory-index` remains a memory-only deprecated alias for at least one minor version,
with a one-line stderr notice that leaves JSON stdout intact.

## Pre-check

This is an informational migration: do not restructure user data or edit configuration.

## Changes

No required changes. The first regeneration changes generated-by command headers once
(benign drift); normal memory index output otherwise retains its byte-stable format.
To index additional roots, add `docs_index.roots` entries in `fab/project/config.yaml`,
keeping an explicit memory entry with `log: true` if memory should still be indexed.
See `fab config explain docs_index.roots` for the schema.

Use `fab docs-index` for all configured roots, or `fab docs-index docs/specs` for one.
First-run curated navigation is imported automatically; no force/adopt flag or mandatory
frontmatter backfill is needed. Accepted README landings preserve prose outside generated
blocks. Primary index landings remain generated whole files. Additional roots default to
`log: false`; FKF writing rules do not become requirements on spec content.

## Verification

Existing scripts using the alias continue to run. A normal regeneration followed by
`fab docs-index docs/memory --check` reports the same graded checks (0/1/2), with blocking
findings independent of drift. No migration writes are necessary; re-reading this note
is a no-op.
