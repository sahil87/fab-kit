# Migration: 2.29.0 to 2.30.0

> The exact version range is a placeholder — the slot this change ships in is
> release-owned and set at release time.

## Summary

The `fab operator` command family and its verbs are gone. The operator lives in
HexoKit: use `rk operator`, read its chat skill with `rk skill operator`, and run
its merge automation with `rk operator autopilot`.

The project-level `/fab-operator` skill is removed too; use `rk operator` or
`rk skill operator` directly. Fab no longer writes a user-level `fab-operator`
skill under `~/`. Instead, `fab sync` removes
previously fab-generated copies from `~/.agents/skills/fab-operator/` and
`~/.claude/skills/fab-operator/` while preserving foreign files, symlinks, and
non-empty directories.

Fab's `autopilot.merge_mode` config key is retired. HexoKit reads
`operator.merge_mode` from rk settings and never reads fab's old key.

**This migration performs no automated file edits.** Fab's operator state file is
left untouched for `rk operator adopt` to read.

## Pre-check

1. Inspect `fab/project/config.yaml` and `fab config show --system` for a legacy
   `autopilot.merge_mode` setting and note its value.
2. If you still used fab's operator because rk could not serve `rk skill
   operator`, install or upgrade HexoKit before continuing.
3. Check whether fab's operator state still contains tracked items that have not
   been imported into HexoKit.

## Changes

1. If `autopilot.merge_mode` was set to `<value>`, run:

   ```sh
   rk settings set operator.merge_mode <value>
   ```

   Otherwise rk's autopilot silently uses `cherry-pick-ladder`.

2. Delete the now-inert `autopilot:` block by hand from
   `fab/project/config.yaml` and, if present, `~/.fab-kit/config.yaml`. The
   retired key is no longer recognized by `fab config unset`, so edit the file
   directly.
3. If fab's state file holds items not yet imported, run `rk operator adopt`.
   It is idempotent and only reads fab's state file.
4. Run `fab sync` in a fab project to remove stale fab-generated user-level
   pointer copies. If either copy was edited, review and remove it by hand; sync
   deliberately preserves files without fab's generated-by marker.

## Verification

1. `fab operator` fails as an unknown command; use `rk operator` instead.
2. `/fab-operator` no longer exists in a fab project; use `rk operator` or read
   `rk skill operator` directly.
3. After `fab sync`, fab-generated copies under
   `~/.agents/skills/fab-operator/` and `~/.claude/skills/fab-operator/` are
   gone. Edited or foreign copies require manual review.
4. `rk settings get operator.merge_mode` shows the intended merge mode.
